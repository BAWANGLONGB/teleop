# PICO → Marvin 首次部署（PC Service 与 PICO）

本文只覆盖 PICO、XRoboToolkit PC Service、Python 工程和 Marvin 实机的首次部署，
不包含 MuJoCo。首次实机动作必须在本流程全部通过、现场清场并安排观察员后进行。

## 1. 安全和网络拓扑

```text
PICO XRoboToolkit App ──Wi-Fi/TCP 63901──> PC Service
                                               │
                         Python XrClient <──本机 gRPC 60061
                                               │
                         Marvin SDK ──独立有线网──> 机器人控制器
```

- PICO 只填写服务电脑的局域网 IPv4 地址，不能填写 `127.0.0.1`；
- Python 程序连接本机 `127.0.0.1:60061`，不直接连接 PICO；
- 建议服务电脑用 Wi-Fi 连接 PICO，用独立有线网卡连接 Marvin；两张网卡不要桥接；
- PICO 网络和 Marvin 控制网络应使用不同网段；
- 机械臂工作区清空，物理急停在观察员手边。程序退出不能替代物理急停。

## 2. 准备安装文件

推荐系统为 Ubuntu 22.04 x86_64。安装文件的版本、SHA-256 和官方来源集中记录在
[`pico-service-software/README.md`](../../pico-service-software/README.md)，对应校验清单为
[`SHA256SUMS`](../../pico-service-software/SHA256SUMS)。优先使用仓库中的本地文件：

```text
/home/zxcx/TeleOp/pico-service-software/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb
/home/zxcx/TeleOp/pico-service-software/XRoboToolkit-PICO-1.1.1.apk
```

本地文件缺失时，在仓库根目录执行以下命令获取两个安装文件：

```bash
mkdir -p pico-service-software
curl -fL \
  -o pico-service-software/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb \
  'https://github.com/XR-Robotics/XRoboToolkit-PC-Service/releases/download/v1.0.0/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb'

curl -fL \
  -o pico-service-software/XRoboToolkit-PICO-1.1.1.apk \
  'https://github.com/XR-Robotics/XRoboToolkit-Unity-Client/releases/download/v1.1.1/XRoboToolkit-PICO-1.1.1.apk'
```

两个文件都从官方 Release 获取，保存到 `pico-service-software/` 后校验：

```bash
sha256sum -c pico-service-software/SHA256SUMS
```

只有两个结果都为 `OK` 才继续安装。安装包不会提交到普通 Git；上述官方来源和校验清单
确保新服务电脑可以复现同一版本。

## 3. 服务电脑安装

### 3.1 安装系统依赖

```bash
sudo apt update
sudo apt install -y android-tools-adb build-essential pybind11-dev libjson-c-dev
```

`android-tools-adb` 只用于给 PICO 安装 APK；正式位姿数据通过 Wi-Fi 传输。

### 3.2 安装 PC Service

```bash
sudo dpkg -i /home/zxcx/TeleOp/pico-service-software/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb
sudo apt-get -f install
dpkg-query -W -f='${Status} ${Version}\n' roboticsservice
```

预期看到 `install ok installed 1.0.0.0`。安装目录应为：

```text
/opt/apps/roboticsservice/
├── RoboticsServiceProcess
├── runService.sh
└── libPXREAGRPCServer.so
```

### 3.3 配置服务电脑网络

查看所有 IPv4 地址：

```bash
ip -brief -4 addr show scope global
```

记录连接 PICO 的 Wi-Fi 地址，例如 `192.168.120.115`。PICO 和该地址必须处于同一
局域网且互相可达。若启用了 UFW，只开放 PICO 到服务端的入口：

```bash
sudo ufw allow 63901/tcp
sudo ufw status
```

不要把 `60061` 暴露到局域网；不要为了排查问题关闭全部防火墙。

### 3.4 启动和检查 PC Service

```bash
bash /opt/apps/roboticsservice/runService.sh
pgrep -af RoboticsServiceProcess
ss -lnt | grep -E ':(63901|60061)\b'
```

`runService.sh` 只启动后台服务。不要用 `run3D.sh` 代替它，3D Demo 不是本项目
所需的服务入口，也可能造成重复进程。

预期：`63901` 监听 PICO，`60061` 由 Python SDK 在本机使用。若已有旧的
`RoboticsServiceProcess`，先结束旧进程再启动一个实例。

## 4. PICO 安装与配置

### 4.1 开启开发者模式和 USB 调试

在 PICO 中打开系统设置，进入“关于本机/软件信息”，连续点击版本号以开启开发者
选项；在开发者选项中开启 USB 调试。不同 PICO 固件的菜单名称可能略有差异，
以当前系统显示为准。

使用 USB 数据线连接服务电脑，接受头显中的“允许 USB 调试”授权：

```bash
adb devices -l
```

设备应显示为 `device`。若显示 `unauthorized`，在头显中确认授权；没有设备时先
更换 USB 数据线/接口并确认开发者模式已开启。

### 4.2 安装 XRoboToolkit App

```bash
adb install -r /home/zxcx/TeleOp/pico-service-software/XRoboToolkit-PICO-1.1.1.apk
```

安装成功后，在 PICO 应用列表打开 `XRoboToolkit`。如果无法使用 ADB，可将 APK
复制到头显存储，再用 PICO 文件管理器打开并安装；正式运行不需要保持 USB 连接。

### 4.3 配置 PICO 到 PC Service

在 XRoboToolkit 中：

1. 打开 `Data & Control → PC Service → Enter`；
2. 填写服务电脑连接 PICO 的 Wi-Fi IPv4 地址，例如 `192.168.120.115`；
3. 确认 `Network=WORKING`；
4. 打开 `Head`、`Controller` 和 `Send`；
5. 关闭 `Switch w/ A Button`，避免 A 键切换数据发送状态；
6. 确认左右手柄已连接，并保持头显唤醒。

PICO 不填写 Marvin 控制器地址。Marvin 的 `192.168.1.190` 只配置在服务电脑的
实机启动参数中。

## 6. PICO-only 连通性验证

在 `xr-marvin-teleop` 目录、`Teleop` 环境中执行：

```bash
python - <<'PY'
from contextlib import closing
from xr_marvin_teleop.common.xr_client import XrClient

with closing(XrClient()) as client:
    first = client.wait_for_fresh_snapshot(timeout_seconds=2.0)
    print("first:", first.timestamp_ns, first.grip_values)
    for _ in range(5):
        snapshot = client.wait_for_fresh_snapshot(timeout_seconds=2.0)
        print("frame:", snapshot.timestamp_ns,
              "left=", snapshot.left_controller_pose[:3],
              "right=", snapshot.right_controller_pose[:3])
PY
```

通过标准：

- 打印 `PICO XR stream ready.`；
- 时间戳大于 0 且持续递增；
- 手柄移动时位置数据变化；
- Grip、Trigger 和摇杆字段在范围内变化。

只看到 `server connect` 不代表 PICO 已发送追踪帧。超时依次检查：PC Service 进程、
`63901` 端口、PICO IP 是否填成 Wi-Fi 地址、PICO 是否为 `WORKING`、`Controller`
和 `Send` 是否打开。

## 7. 首次实机启动

### 7.1 Marvin SDK 文件和配置

Python 封装和配置文件已在本仓库中；`libMarvinSDK.so`、`libKine.so` 等 Linux 动态库
是被 Git 排除的构建产物。新机器没有这些 `.so` 时，在仓库已有的 SDK 源码上编译，
不需要从当前电脑复制：

```bash
cd /home/zxcx/TeleOp/TJArm/tj_fx_robot-master
chmod +x marvinSDK_ubuntu_100343.sh
./marvinSDK_ubuntu_100343.sh
```

脚本会从 `contrlSDK100343/`、`kinematicsSDK/` 和 `interferenceCheck/` 的已上传源码
生成并复制 Linux 库。编译器应为 x86_64 Ubuntu 22.04 环境中的 `g++`；若现场 SDK
版本与仓库源码不一致，停止部署并先确认厂家版本。

确认 SDK 根目录包含：

```text
SDK_PYTHON/fx_robot.py
SDK_PYTHON/libMarvinSDK.so
SDK_PYTHON/fx_kine.py
SDK_PYTHON/libKine.so
CommonConfig/config/ccs_680.MvKDCfg
robot.ini
```

`robot.ini` 必须保持 `R.BASIC/UseEMG=1`，双臂 `JointPIDCtlType=1`。确认当前 Tool
与 `TJArm/tools_cfg.json` 的 active tool 一致，A/B 关节映射、机器人型号和 IP 也须
由现场确认。

### 7.2 普通 IK 基线

首次动作先不启用 NSP、不启用夹爪：

```bash
python scripts/hardware/teleop_marvin_hardware.py \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --confirmed-robot-model "M6S-Lite-CCS-680-B" \
  --robot-ip 192.168.1.190 \
  --control-hz 50 \
  --joint-velocity-ratio 10 \
  --joint-acceleration-ratio 10
```

双 Grip 松开时机器人应保持当前位置。通过后才启用动态 NSP：

```bash
python scripts/hardware/teleop_marvin_hardware.py \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --confirmed-robot-model "M6S-Lite-CCS-680-B" \
  --nsp-lateral --nsp-max-angle 5
```

`5°` 是动态 `ZSP_Angle` 的最大偏角，不是启动时固定发送的角度。夹爪必须在厂商
协议确认并完成空载测试后，才通过 `--gripper-config PATH` 启用。

## 8. 部署完成标准与故障处理

- [ ] PC Service 只有一个实例，`63901/60061` 端口正常；
- [ ] PICO 显示 `Network=WORKING`，PICO-only 帧连续递增；
- [ ] PICO 端未填写 `127.0.0.1` 或 Marvin 控制器地址；
- [ ] 普通 IK 下单臂小动作方向正确，双 Grip 松开后保持；
- [ ] 物理急停测试通过，观察员在场；
- [ ] SDK 文件、Tool、A/B 映射和机器人型号已核对；
- [ ] 日志已写入 `xr-marvin-teleop/logs/`。

常见问题：

| 现象 | 处理 |
| --- | --- |
| `adb` 无设备 | 检查 USB 数据线、USB 调试授权和开发者模式 |
| PICO 不是 `WORKING` | 检查 PC Wi-Fi 地址、同网段和 `63901/tcp` |
| `PICO XR stream` 超时 | 确认 `Controller`、`Send` 已开启且头显未休眠 |
| `Marvin reported error codes` | 停止动作，检查机器人状态和物理急停 |
| `idle mode switch response timed out` | 保持急停可用，检查机器人网络，不要假定已 idle |
| IK 无解 | 保持上一目标，检查 Tool、工作空间和关节边界 |

遇到异常运动先触发物理急停，再保留终端错误、启动命令和日志进行排查。
