# PICO → Marvin 日常操作说明

本文用于首次部署完成后的日常遥操和数据采集。推荐流程为：PICO、左右 DAS 串口和
左右相机分别在独立进程运行；控制任务订阅 PICO/DAS 并控制 Marvin、发布夹爪命令，
相机把原生 MJPEG 直接写入 MCAP。每次启动前仍必须完成急停、清场和设备检查。

## 1. 启动前安全检查

1. 机械臂工作区无人、无障碍物，观察员位于物理急停旁；
2. Marvin 无错误并处于静止/低速状态；
3. Robot 型号、Tool、A/B 关节映射和机器人 IP 未改变；
4. PICO 显示 `Network=WORKING`，`Controller`、`Send` 已打开；
5. `Switch w/ A Button` 关闭，头显和左右手柄保持唤醒；
6. 双 Grip、双 Trigger 松开，双摇杆居中；
7. DAS 夹爪周围无异物，左右串口和相机设备存在；
8. 数据盘空间足够；按相机实际 MJPEG 码率预留空间；
9. 确认位移比例适合当前任务：优先使用显式 `--scale-factor`，否则读取已有 scale 标定；
   `logs/marvin_scale_calibration.json` 缺失时自动生成默认比例 `1.2` 的文件，无需先做 A/A 标定。

检查 DAS 设备：

```bash
ls -l \
  /dev/ttyFingerLeft \
  /dev/ttyFingerRight \
  /dev/finger_camera_left \
  /dev/finger_camera_right
```

确认两路相机支持配置中的 MJPEG 分辨率和帧率：

```bash
v4l2-ctl --device /dev/finger_camera_left --list-formats-ext
v4l2-ctl --device /dev/finger_camera_right --list-formats-ext
```

检查磁盘空间：

```bash
df -h /home/zxcx/TeleOp/xr-marvin-teleop
```

当前 DAS 配置文件为
[`config/das_gripper.example.json`](../config/das_gripper.example.json)。运行前必须确认
其中的 `serial_port`、`camera_device`、开闭距离、启动距离、`invert` 和相机参数与实机一致。
示例默认最小距离为 `0.000 m`、最大开口为 `0.150 m`、安全启动距离为 `0.050 m`。
逻辑左相机读取 `/dev/finger_camera_left`，逻辑右相机读取 `/dev/finger_camera_right`。
预览和 MCAP 话题沿用采集侧标签，不再额外交换。更换 USB 接口或修改 udev 规则后，
应遮挡单侧镜头核对预览和话题；夹爪串口保持原来的左右映射。


相机分辨率在左右两侧配置的 `camera_resolution` 中选择，标准数采命令不需要额外的
命令行参数：

```json
{
  "left": {
    "camera_fps": 60,
    "camera_resolution": "640x480",
    "camera_latency_ms": 24.0
  },
  "right": {
    "camera_fps": 60,
    "camera_resolution": "640x480",
    "camera_latency_ms": 25.0
  }
}
```

- `640x480`：历史标定使用上面的左右延迟值。
- `1600x1296`：可选高分辨率；将左右 `camera_resolution` 改为该值，并将左右
  `camera_latency_ms` 分别设为实测值 `22.0` 和 `24.0`。
- `camera_fps` 保持 `60` 时，厂家相机实际输出约 `30 fps`。高分辨率会显著增加磁盘
  占用，正式采集前应先完成短时测试并检查 `v4l2` 协商结果。

`camera_latency_ms` 保留在配置快照中，当前录制和导出不扣除它。需要排查曝光或协商参数时，
在采集前运行 `v4l2-ctl --device /dev/finger_camera_left --all`（右侧同理）；录制进程只输出首帧就绪摘要，
不在取帧循环里执行外部诊断命令。

```bash
source /home/zxcx/TeleOp/.miniconda-xr/etc/profile.d/conda.sh

python -m pip install -r \
  /home/zxcx/TeleOp/gen_finger_con_python_sdk_release/requirements.txt
```

构建 ROS2 消息：

```bash
source /opt/ros/humble/setup.bash

  --cmake-args \
```

不能开始正式采集。两个 `gst-inspect-1.0` 命令也必须成功找到插件。

## 5. 推荐启动流程：一条命令采集

Pico PC Service 启动并通过第 1 节检查后，执行第 3 节公共环境，然后运行：

```bash
source /home/zxcx/TeleOp/.miniconda-xr/etc/profile.d/conda.sh
conda activate Teleop

source /opt/ros/humble/setup.bash
source /home/zxcx/TeleOp/xr-marvin-teleop/ros2_ws/install/setup.bash

unset LD_PRELOAD

cd /home/zxcx/TeleOp/xr-marvin-teleop
```

```bash
python scripts/data/run_collection.py \
  --task pick_and_place \
  --operator zxcx \
  --robot-model "M6S-Lite-CCS-680-B" \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --das-config config/das_gripper.example.json \
  --das-sdk-root /home/zxcx/TeleOp/gen_finger_con_python_sdk_release
```

supervisor 会自动完成：

1. 检查 MCAP 插件、DAS 配置、左右串口/相机、scale 标定和输出盘空间；
2. 启动 PICO publisher，并等待 `/raw/pico/frame` 出现新鲜有效帧；
3. 启动左右独立 DAS source，完成夹爪自检并等待左右编码器有效反馈；
4. 启动状态 recorder 和左右 MJPEG writer，等待两路相机首帧写盘；
5. 最后使能 Marvin 控制；
6. 监控所有关键子进程，任一异常退出时停止整项任务；
7. 收到一次 `Ctrl+C` 后，依次停止 Marvin、DAS、关闭原始 MCAP、停止 PICO；manifest 在离线校验时生成。

实际进程结构：

```text
run_collection.py
├── publish_pico.py
├── publish_das.py --side left       # 独占左串口
├── publish_das.py --side right      # 独占右串口
├── record_episode.py
│   ├── ros2 bag record              # state/
│   ├── capture_das_mjpeg.py left    # vision_left/
│   └── capture_das_mjpeg.py right   # vision_right/
└── teleop_marvin_hardware.py        # Marvin 控制，不访问相机或 DAS 串口
```

相机进程从 V4L2 取得原生 MJPEG 后直接调用 `rosbag2_py` 写 MCAP，不发布 ROS 图像，
不经过 DDS、JPEG 解码或重新编码。ROS2 只承载 PICO、机械臂、夹爪和诊断数据。

`config/collection.json` 默认使用以下调度，可通过 `runtime.cpus` / `runtime.nice` 修改；recorder 启动的状态与相机写盘子进程会继承其 CPU
亲和性和 `nice` 值：

| 任务 | 逻辑 CPU | nice |
| --- | --- | --- |
| Marvin 控制 | `2,3,18,19` | `0` |
| PICO publisher | `4,20` | `0` |
| 左 DAS 串口 | `5,21` | `0` |
| 右 DAS 串口 | `6,22` | `0` |
| recorder | `7-15,23-31` | `+10` |

`0,1,16,17` 留给系统和 supervisor。启动时若这些 CPU 不可用，preflight 会直接报错，
不会在未隔离状态下继续使能硬件。

默认自动使用并保存以下两个标定快照：

```text
config/das_gripper.example.json
logs/marvin_scale_calibration.json
```

需要 NSP 和附加元数据时追加：

```bash
python scripts/data/run_collection.py \
  --task pick_and_place \
  --operator zxcx \
  --robot-model "M6S-Lite-CCS-680-B" \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --das-config config/das_gripper.example.json \
  --das-sdk-root /home/zxcx/TeleOp/gen_finger_con_python_sdk_release \
  --nsp-lateral \
  --nsp-max-angle 5 \
  --nsp-angle-rate 20 \
  --metadata scene=table \
  --notes "trial 01"
```

可选使用 `--max-duration 120` 自动结束，或用 `--no-vision` 进行无图像调试。
左右 NSP 方向需要校准时可追加 `--nsp-lateral-sign-left/right {-1,1}`；额外标定文件
可重复使用 `--calibration PATH` 保存到 episode。
Pico PC Service 和物理急停检查不会由 supervisor 自动启动或代替。

## 6. 手动启动流程：仅用于排障

严格按照“PICO → DAS → recorder → Marvin 控制”的顺序启动。

```bash
source /home/zxcx/TeleOp/.miniconda-xr/etc/profile.d/conda.sh
conda activate Teleop

source /opt/ros/humble/setup.bash
source /home/zxcx/TeleOp/xr-marvin-teleop/ros2_ws/install/setup.bash

unset LD_PRELOAD

cd /home/zxcx/TeleOp/xr-marvin-teleop
```

### 6.1 终端 1：PICO 原始数据发布

先执行第 3 节公共环境，再运行：

```bash
python scripts/data/publish_pico.py --poll-hz 120
```

首次运行可在另一个已配置环境的终端确认：

```bash
ros2 topic hz /raw/pico/frame
ros2 topic echo /raw/pico/frame --once
```

只有消息持续更新且 `valid: true` 时才能继续。

### 6.2 终端 2/3：DAS 原始数据与夹爪执行

先执行第 3 节公共环境，再运行：

```bash
python scripts/data/publish_das.py \
  --side left \
  --config config/das_gripper.example.json \
  --sdk-root /home/zxcx/TeleOp/gen_finger_con_python_sdk_release

# 另一个终端启动右侧
python scripts/data/publish_das.py \
  --side right \
  --config config/das_gripper.example.json \
  --sdk-root /home/zxcx/TeleOp/gen_finger_con_python_sdk_release
```

只有两个终端都打印对应侧 `DAS ... source ready`，且左右 `/raw/das/*/state` 持续更新
后才能继续。

### 6.3 终端 4：开始 MCAP 录制

先执行第 3 节公共环境，再运行：

```bash
python scripts/data/record_episode.py \
  --task pick_and_place \
  --operator zxcx \
  --robot-model "M6S-Lite-CCS-680-B" \
  --das-config config/das_gripper.example.json \
  --calibration config/das_gripper.example.json
```

如果 scale 标定文件已经存在，应同时保存它的快照：

```bash
python scripts/data/record_episode.py \
  --task pick_and_place \
  --operator zxcx \
  --robot-model "M6S-Lite-CCS-680-B" \
  --das-config config/das_gripper.example.json \
  --calibration config/das_gripper.example.json \
  --calibration logs/marvin_scale_calibration.json
```

可选参数：

```text
--max-duration 120       录制 120 秒后自动停止
--metadata scene=table   写入额外 episode 元数据
--notes "trial 01"       写入操作备注
--no-vision              仅用于无图像调试，不启动相机 writer
```

录制器打印 `Recording episode_...` 后再启动实机控制。

### 6.4 终端 5：启动 Marvin 控制

先执行第 3 节公共环境。再次确认物理急停、A/B 映射和准确机型后运行：

```bash
python scripts/hardware/teleop_marvin_hardware.py \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --confirmed-robot-model "M6S-Lite-CCS-680-B" \
  --das-gripper-config config/das_gripper.example.json \
  --das-from-ros2 \
  --ros2 \
  --pico-from-ros2
```

需要动态 NSP 时使用（参数沿用 `lateral` 名称，当前实际读取 Marvin X / OpenXR Z）：

```bash
python scripts/hardware/teleop_marvin_hardware.py \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --confirmed-robot-model "M6S-Lite-CCS-680-B" \
  --das-gripper-config config/das_gripper.example.json \
  --das-from-ros2 \
  --ros2 \
  --pico-from-ros2 \
  --nsp-lateral \
  --nsp-max-angle 5 \
  --nsp-angle-rate 20
```

NSP 默认死区为 `0.03 m`、满量程为 `0.12 m`。左右方向不符合实机时，停止
控制并在重新确认后使用 `--nsp-lateral-sign-left/right {-1,1}`；不要在运行中试探。

### 6.5 终端 6：采集状态监控

先执行第 3 节公共环境，然后检查话题：

```bash
ros2 topic list | sort

timeout 10 ros2 topic hz /raw/pico/frame
timeout 10 ros2 topic hz /raw/marvin/joint_state
timeout 10 ros2 topic hz /command/marvin/joint_target
timeout 10 ros2 topic hz /raw/das/left/state
timeout 10 ros2 topic hz /raw/das/right/state
timeout 10 ros2 topic hz /raw/das/left/tactile
timeout 10 ros2 topic hz /raw/das/right/tactile
```

图像不经过 ROS2；录制器只有在左右 MJPEG writer 都写入首帧后才会打印
`Recording episode_...`，对应 `vision_left_recorder.log` 和
`vision_right_recorder.log` 会记录设备、分辨率、帧率及首帧时相机驱动报告的完整
V4L2 参数（包括自动/手动曝光状态、曝光值、增益和白平衡等）。

查看队列丢帧和发布错误：

```bash
ros2 topic echo /diagnostics
```

`/diagnostics` 中异常增加的 `last_encoder_age_ms`、`dropped_state`、
`dropped_tactile`、`dropped_critical` 或 `dropped_publish_error` 表示本次采集质量下降，
应先排查再继续正式任务。

## 8. 手柄操作

| 操作 | 效果 |
| --- | --- |
| 左 Grip 按下 | 从当前手柄姿态和 A 臂 TCP 重新锚定，控制左臂 |
| 右 Grip 按下 | 从当前手柄姿态和 B 臂 TCP 重新锚定，控制右臂 |
| Grip 持续按住 | 手柄相对位姿映射到对应 TCP，持续求 IK |
| Grip 松开 | 对应手臂锁存当前反馈关节角并保持 |
| 双 Grip 松开后按 B | 双臂沿默认 3 秒余弦轨迹返回初始姿态；启用夹爪时同时设为全闭目标 |
| 回位中按某侧 Grip | 取消该侧回位并重新开始遥操 |
| 双 Grip 松开后按 A（第一次） | 采集双臂自然下垂姿态 |
| 双 Grip 松开后按 A（第二次） | 采集双臂水平前伸姿态并保存 scale |

Grip 使用上升沿重新锚定，手柄绝对位置不会直接造成机器人跳变。任一 Grip 按下时 B
会被忽略；Grip 按下、回位运行或机器人非低速时 A 会被忽略。

正式 episode 内不要执行 A/A scale 标定。需要重新标定时先结束当前采集，完成标定并
确认 `logs/marvin_scale_calibration.json` 后，再启动新的 episode，确保标定快照一致。
当前 A/A 接受方向仍使用固定的 Marvin `+Y/+Z` 参考，与现行 OpenXR 前方映射不是同一轴；
现场标定前核对[标定方向约束](architecture-and-interface-spec.md#54-aa-scale-标定)。

## 9. DAS 夹爪操作与标定

闭合度范围为 `0`（全开）到 `1`（全闭），输入采用增量控制：

- 对应 Trigger 扣下：增量闭合；
- 摇杆向后拉：增量闭合；
- 摇杆向前推：增量打开；
- 输入回中：保持当前位置；
- 闭合和打开输入同时存在：闭合优先；
- 前后方向相反：重新启动时增加 `--thumbstick-y-sign -1`。

夹爪目标最多按 `20 Hz` 下发。闭合度 `1` 默认映射到 `0.000 m`，但串口启动时先使用
`startup_distance_m=0.050 m`；取得首个有效编码器反馈后先保持反馈位置，再接受 ROS2
控制命令。程序退出或 PICO stale 不会自动打开夹爪。

DAS source 在 Marvin 连接前先完成自检。若报告编码器值 `-66.66`，不得继续遥操；
清空对应夹爪后单独执行：

```bash
cd /home/zxcx/TeleOp/xr-marvin-teleop

python scripts/hardware/calibrate_das_finger.py \
  --config config/das_gripper.example.json \
  --side left \
  --confirmed-gripper-clear

python scripts/hardware/calibrate_das_finger.py \
  --config config/das_gripper.example.json \
  --side right \
  --confirmed-gripper-clear
```

`closed_distance_m`、`open_distance_m` 和安全 `startup_distance_m` 必须通过空载测试
确认；默认最小值 `0 m` 不代表每套机械结构都允许无负载闭合到底，遥操程序不会自动
修改这些标定值。

## 10. 正常关闭顺序

使用 `run_collection.py` 时，松开双 Grip 后在 supervisor 终端按一次 `Ctrl+C`。
supervisor 会等待 Marvin idle，再停止 DAS，随后停止 recorder 并关闭
原始 MCAP，最后停止 PICO；终端返回前不要关闭窗口或重复发送信号。录制结束不自动打包；在 UI 数据集页面选择格式后点击“打包并导出”。设备可保持运行，打包时不能开始新录制。

手动分终端运行时，必须按以下顺序关闭：

1. 松开双 Grip，停止手柄动作；
2. 在终端 5 按 `Ctrl+C`，等待 Marvin 进入 idle 并释放控制连接；
3. 在终端 2/3 按 `Ctrl+C`，停止左右 DAS SDK；
4. 在终端 4 按 `Ctrl+C`，等待三个原始分片关闭，记录为待导出；
5. 在终端 1 按 `Ctrl+C`，停止 PICO 发布；
6. 在 UI 确认 Episode 状态后再关闭 PC Service。

不要先关闭 recorder，否则会丢失机器人退出阶段的数据。出现异常运动时先触发物理
急停，再处理终端错误；程序退出不能替代急停。

## 11. Episode 数据检查

数采主配置为 `config/collection.json`，可用 `--config` 传入局部 JSON 覆盖；CLI 显式参数优先。
启动前用 `python scripts/data/run_collection.py --print-effective-config` 检查生效配置，此命令不连接设备。
型号、IP、CPU 绑定、采样/预览频率、缓存、超时及编码参数均由主配置管理；左右相机设置仍在引用的 DAS JSON 中。
详细分组与覆盖规则见 [README 数采配置](../README.md#ros2-数据采集可选)。

录制过程中使用以下临时结构：

```text
dataset/session_<date>/episode_<time>_<id>/
├── state/
├── vision_left/
├── vision_right/
├── calibration/
├── config/                 # 生效配置、引用文件快照和 SHA-256 清单
├── metadata.json
├── state_recorder.log
├── vision_left_recorder.log
└── vision_right_recorder.log
```

前三个 bag 是在线隔离写入的原始分片。UI / supervisor 在停止录制后只保存原始数据；在数据集页面选择 `.h264.mcap` 或 `.mjpeg.mcap` 后打包下载。
`manifest.json` 由后处理校验生成，录制中没有该文件是正常现象。
设备可保持运行；后处理保留系统时间、补充双臂反馈/目标 TCP 6D pose，并生成：

```text
episode_<time>_<id>/final/
├── episode_<time>_<id>.mjpeg.mcap
└── episode_<time>_<id>.h264.mcap
```

每个文件独立包含完整状态、指令、触觉、TCP 和两路画面，不依赖外部视频。
MJPEG 直接使用原始 JPEG 字节和 `foxglove.CompressedImage`；H.264 使用
`foxglove.CompressedVideo`，每个消息一个 Annex B AU，无 B 帧，IDR 带 SPS/PPS。
状态保留 ROS2 CDR/schema；图像使用 Protobuf/schema。元数据和标定使用 MCAP Attachment。
整组输出在 CRC/消息数量校验后才原子发布到 `final/`；原始目录不自动删除，支持恢复和重新调参。
这不是纯 ROS2 profile，不应直接用 `ros2 bag play` 播放混合编码文件。

### 11.1 统一时间轴与主要话题

各进程运行在同一台采集机上，使用 Linux 系统时间 `CLOCK_REALTIME`：

```text
final_mcap_time_ns = acquisition_header_stamp_ns
```

最终时间戳按以下优先级选择：

1. `header.stamp`（相机为 `image.header.stamp`）；
2. 无 header 的 Episode 消息中的 `wall_time_ns`；
3. 无采集时间时使用原始 `bag_time_ns`。多发布者的 `/diagnostics` 固定使用 bag 系统时间。

不再通过单调时钟估算墙钟，也不扣除 `camera_latency_ms`。历史配置可保留，但当前录制和
导出不应用它。采集系统时间原样写入最终 MCAP 的 log/publish time 及图像消息 timestamp，
不是转码时的系统时间。系统校时产生的回退会保留并由验证报告标记，不静默修改时间戳。

主要数据话题：

| 数据 | 话题 |
| --- | --- |
| 关节反馈/速度 | `/raw/marvin/joint_state` |
| 关节目标 | `/command/marvin/joint_target` |
| TCP 反馈/目标 | `/raw/marvin/{left,right}/tcp_pose`、`/command/marvin/{left,right}/tcp_target` |
| PICO/VR | `/raw/pico/frame` |
| 左右触觉 | `/raw/das/{left,right}/tactile` |
| MJPEG 画面 | `/raw/das/{left,right}/image/compressed` |
| H.264 画面 | `/raw/das/{left,right}/video/compressed` |

相机系统时间是软件取帧时间，不是硬件曝光时间；当前明确不补偿相机缓存或 USB 时延。

### 11.2 完整性校验

离线后处理先校验原始/合并 ROS bag，再生成并校验最终 MCAP。最终状态和原始 manifest
保存在 MCAP 的 `meta/meta.json` 中。

```bash
python -m json.tool dataset/session_YYYY-MM-DD/episode_<time>_<id>/manifest.json
```

结果含义：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `validated` | 必需话题完整且未检测到时序/序号异常 | 可进入后续处理 |
| `degraded` | 存在时间回退或序号缺口 | 人工检查后决定是否保留 |
| `rejected` | 缺少 PICO、Marvin、关节命令或预期图像 | 不进入训练数据集 |

### 11.3 导出最终 MCAP

UI 数据集页面可选择格式并“打包并导出”；手动打包或重试时，安装依赖并在录制停止后运行：

```bash
python -m pip install -e '.[h264]'
python scripts/data/postprocess_episode.py dataset/session_YYYY-MM-DD/episode_<time>_<id>
```

`run_collection.py`、`record_episode.py` 和后处理命令均接受 `--no-mjpeg` / `--no-h264`；
至少开启一种。H.264 可调整 `--h264-crf 23`（1–51）、`--h264-preset veryfast`、
`--h264-keyint 60`（帧）和 `--h264-threads 2`（1–16）。后处理默认继承录制时保存的参数。
新 Episode 同时保存主配置快照及引用文件，后处理从快照读取；公共配置后续修改不影响历史数据。
离线 `--config` 仅允许覆盖 `export` 和 `runtime.export_nice`，原始采集设置不会被导出参数覆盖。
关闭最终 MJPEG 不影响用于 H.264 转码的临时 JPEG 录制。

离线后处理以低 CPU 优先级执行；同一 `--output-root` 下的录制与导出互斥，
冲突时立即报忙，不等待；`--part devices` 可保持运行。
已有 `final/` 不覆盖，重导出需先移走旧 `final/`；原始 bag 保留，确认后人工归档/清理。
UI 可按需打包并下载 H.264 或 MJPEG MCAP；历史视频尚不支持页内播放，使用 Foxglove 查看。

### 11.4 人工审阅

直接在 Foxglove 打开任一最终 MCAP，在 Image 面板选择左右图像/视频话题，并检查对应
时间点的状态和动作。无需解包。原 ROS bag 审阅脚本仍可用于保留的原始目录。
若画面冻结但状态继续变化，或时间差突然跳变，应将 Episode 标记为异常并结合内嵌的
`validation`、`topic_counts` 和原始目录中的日志定位。

## 12. JSONL 调试与故障留档

硬件控制仍会生成：

```text
logs/marvin_hardware_<timestamp>.jsonl
```

回放命令目标或反馈：

```bash
python scripts/simulation/replay_marvin_log.py \
  logs/marvin_hardware_<timestamp>.jsonl --source command --headless

python scripts/simulation/replay_marvin_log.py \
  logs/marvin_hardware_<timestamp>.jsonl --source feedback --headless
```

故障定位应保留：完整启动命令、终端 traceback、Marvin 错误码、JSONL、episode
目录、`state_recorder.log`、左右 `vision_*_recorder.log` 和当时的 PICO 按键状态。

JSONL 和采集目录由 Git 忽略，归档需单独管理。`logs/marvin_scale_calibration.json`
是当前标定配置，不能随调试日志清理。常见启动故障见[常见报错](常见报错.md)。
