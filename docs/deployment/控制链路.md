## 完整控制链路
  完整的一次录制由“设备进程 + 控制进程 + Episode 录制进程”协同完成。

  ### 1. 总体进程树

  teleop-collect
  └─ collection.py                    进程监督器
     ├─ cli.pico                      PICO 数据源
     ├─ cli.das --side left           左手 DAS 数据源
     ├─ cli.das --side right          右手 DAS 数据源
     ├─ cli.record                    Episode 录制管理
     │  ├─ ros2 bag record            状态数据 → state MCAP
     │  ├─ cli.capture --side left    左相机 → vision_left MCAP
     │  └─ cli.capture --side right   右相机 → vision_right MCAP
     └─ cli.hardware                  Marvin 实时控制
        └─ controller.py
           └─ marvin.py
              └─ fx_robot.py
                 └─ libMarvinSDK.so

  主监督入口见 src/xr_marvin_teleop/cli/collection.py:556。

  ### 2. 启动阶段

  默认 --part all 的实际启动顺序：

  teleop-collect
    → 解析 collection.json 和命令行参数
    → 创建输出目录
    → 获取 collection 共享锁
    → 获取 devices 独占锁
    → 冻结本次配置快照
    → 执行 preflight
    → 构建所有子进程命令
    → 检查 CPU affinity

  预检查包括：

  - ROS2 和 MCAP 插件是否存在
  - DAS SDK、串口、相机是否存在
  - 标定文件是否有效
  - scale factor 是否可解析
  - 输出磁盘空间
  - 当前设备配置是否和已启动设备一致

  随后按顺序启动：

  1. PICO publisher
  2. 等待 PICO 第一帧
  3. DAS left
  4. DAS right
  5. 等待两侧 DAS encoder 有效
  6. Episode recorder
  7. 等待左右相机输出第一帧
  8. Marvin hardware
  9. 进入监控循环

  对应 src/xr_marvin_teleop/cli/collection.py:595。

  录制器先于 Marvin hardware 启动，因此命令行 --part all 模式下，Marvin 的启动、进入阻抗模式和首个控制命令也会被录到 Episode 中。

  ### 3. 设备数据源

  #### PICO 数据

  PICO SDK
    → XrClient.read_snapshot()
    → cli.pico
    → Ros2DataBridge.publish_pico()
    ├─ /raw/pico/poses
    ├─ /raw/pico/joy
    └─ /raw/pico/status

  PICO 按配置频率轮询，默认约 120 Hz；只发布时间戳发生变化的新帧。

  #### DAS 数据

  左右 DAS 各自一个独立进程：

  DAS Python SDK
    → encoder callback
    → /raw/das/{left|right}/state
    → /raw/das/{left|right}/state/status

  DAS Python SDK
    → tactile callback
    → /raw/das/{left|right}/tactile
    → /raw/das/{left|right}/tactile/status

  DAS 进程同时订阅：

  /command/das/target
  /command/das/target/status

  收到夹爪目标后调用：

  DasSidePublisher._handle_command()
    → gripper_targets()
    → DataBus.set_target_distance()

  见 src/xr_marvin_teleop/cli/das.py:235。

  ### 4. Marvin 控制期间的数据流

  cli.hardware 通过 ROS2 获取 PICO 和 DAS 数据，通过厂商 SDK 控制 Marvin：

  /raw/pico/*
    → RosPicoClient
    → controller.execute_control_cycle()

  /raw/das/*/state
    → RosDasClient
    → controller / gripper health

  每个控制周期：

  读取 PICO
    → 读取 Marvin 反馈
    → XR 坐标转换
    → FK
    → 手柄增量映射
    → IK
    → 关节速度限幅
    → MarvinSdkAdapter.send_joint_command()
    → fx_robot.set_joint_cmd_pose(A/B)
    → fx_robot.send_cmd()
    → libMarvinSDK.so
    → Marvin

  与此同时，硬件控制进程将状态和命令发布到 ROS2：

  Marvin SDK 反馈
    → /raw/marvin/joint_state
    → /raw/marvin/joint_state/status

  控制器目标关节角
    → /command/marvin/joint_target
    → /command/marvin/joint_target/status

  夹爪目标
    → RosDasClient.send_gripper_command()
    → /command/das/target
    → /command/das/target/status

  因此控制和录制是旁路关系：

  实时控制线程 ──→ 机器人
         │
         └──→ ROS2 发布队列 ──→ rosbag recorder

  录包速度不会直接阻塞控制线程；Ros2DataBridge 使用有界队列隔离控制和记录。

  ### 5. Episode 创建

  src/xr_marvin_teleop/cli/record.py:321 启动后：

  确定 Session
    → 生成 episode_HHMMSS_xxxxxxxx
    → 创建 Episode 目录
    → 冻结 collection.json 及引用文件
    → 复制标定文件
    → 生成 metadata.json，status="starting"

  默认路径：

  /home/zxcx/yubing/teleop/var/dataset/
  └─ session_YYYY-MM-DD/
     └─ episode_HHMMSS_xxxxxxxx/

  然后创建三个实际记录器：

  state recorder
    → ros2 bag record --storage mcap
    → 写入 state/

  left camera recorder
    → GStreamer 从左相机读取原生 MJPEG
    → rosbag2_py.SequentialWriter
    → 写入 vision_left/

  right camera recorder
    → GStreamer 从右相机读取原生 MJPEG
    → rosbag2_py.SequentialWriter
    → 写入 vision_right/

  录制器定义见 src/xr_marvin_teleop/cli/record.py:250。

  ### 6. 相机录制链路

  相机不是先发布 ROS2 再被统一 rosbag 订阅，而是直接写独立 MCAP：

  /dev/video*
    → GStreamer v4l2src
    → native MJPEG sample
    → sensor_msgs/CompressedImage
    → rosbag2_py.SequentialWriter.write()
    → vision_left 或 vision_right MCAP

  每帧同时写入：

  /raw/das/{side}/image/compressed
  /raw/das/{side}/image/compressed/status

  见 src/xr_marvin_teleop/cli/capture.py:196。

  第一帧成功写入后，相机创建 .vision_left.ready 或 .vision_right.ready。两边都 ready 后，Episode 才正式进入 recording 状态。

  ### 7. 正式开始录制

  全部记录器就绪后：

  metadata.status = "recording"
    → 发布 /episode/state: recording
    → 发布 /episode/event: start
    → 创建 recorder-ready 文件
    → teleop-collect 宣布 Collection active

  见 src/xr_marvin_teleop/cli/record.py:480。

  state MCAP 记录的主题由 config/collection.json 定义，主要包括：

  PICO：
    /raw/pico/poses
    /raw/pico/joy
    /raw/pico/status

  Marvin：
    /raw/marvin/joint_state
    /raw/marvin/joint_state/status
    /command/marvin/joint_target
    /command/marvin/joint_target/status

  DAS：
    /command/das/target
    /command/das/target/status
    /raw/das/left/state
    /raw/das/right/state
    /raw/das/left/tactile
    /raw/das/right/tactile
    以及对应 status

  Episode：
    /episode/state
    /episode/event

  系统：
    /diagnostics

  所有流通过消息时间戳进行后续同步，不是在录制时强制拼成同一帧。

  ### 8. 停止一次录制

  停止来源可以是：

  - Web UI 点击停止
  - PICO 手柄 X
  - 命令行 Ctrl+C
  - 到达 max_duration
  - 子进程异常退出

  Web UI 路径：

  POST /api/episodes/active/stop
    → stop_collection()
    → SIGINT 发送给 teleop-collect recording 进程组
    → collection.py 设置 stop_requested
    → 开始安全关闭

  手柄 X 路径：

  PICO hotkey
    → Web handle_controller_button()
    → _stop_collection()
    → SIGINT

  ### 9. Episode 收尾

  cli.record 收到 SIGINT 后不会立即杀掉 MCAP writer，而是：

  stop_requested.set()
    → 发布 /episode/event: stop
    → 发布 /episode/state: finalizing
    → 等待 250 ms，使事件进入 state bag
    → 逆序停止 vision_right
    → 停止 vision_left
    → 停止 state rosbag
    → 等待所有 writer 正常关闭
    → metadata.status = "completed"
    → 写入 ended_at_ns
    → export_status = "pending"

  见 src/xr_marvin_teleop/cli/record.py:494。

  正常完成后的目录大致为：

  episode_HHMMSS_xxxxxxxx/
  ├─ metadata.json
  ├─ config/
  │  ├─ collection.json
  │  ├─ files.json
  │  └─ 各配置快照
  ├─ calibration/
  │  └─ 标定文件快照
  ├─ state/
  │  ├─ metadata.yaml
  │  └─ *.mcap
  ├─ vision_left/
  │  ├─ metadata.yaml
  │  └─ *.mcap
  ├─ vision_right/
  │  ├─ metadata.yaml
  │  └─ *.mcap
  ├─ state_recorder.log
  ├─ vision_left_recorder.log
  └─ vision_right_recorder.log

  此时只是原始录制完成，视频转换、派生 TCP 位姿、校验和最终打包不在实时录制链路内；metadata.json 会标记：

  {
    "status": "completed",
    "export_status": "pending"
  }

  需要之后运行 teleop-postprocess。

  ### 10. 两种启动方式的差异

  Web 控制台通常采用分离模式：

  --part devices
    → PICO + DAS left/right + Marvin hardware 常驻

  每次点击录制：
  --part recording
    → 只启动 cli.record
    → 完成一个 Episode
    → 停止后设备继续运行

  命令行默认模式：

  --part all
    → 启动设备
    → 启动一个 Episode
    → 停止时按以下顺序关闭：
        Marvin hardware
        DAS left
        DAS right
        recorder
        PICO

  该顺序刻意让 recorder 最后关闭，以便把机器人退出阻抗模式、进入 idle 和设备停止阶段也记录下来。关闭顺序见 src/xr_marvin_teleop/cli/collection.py:525。



 ## Marvin 控制链路

  hardware.py
    └─ 创建 MarvinSdkAdapter + MarvinHardwareTeleopController
        └─ controller.run()
            ├─ prepare_hardware()       启动与模式配置
            ├─ execute_control_cycle()  50 Hz 实时控制
            └─ shutdown_hardware()      空闲与释放

  ### 1. 启动链路

  src/xr_marvin_teleop/cli/hardware.py:310 创建适配器和控制器，最后调用 teleop_controller.run()。

  controller.run()
    → controller.prepare_hardware()
    → adapter.connect()
    → Marvin_Robot.connect("192.168.1.190")
    → libMarvinSDK.so::OnLinkTo(...)

  marvin.py 加载厂商 SDK 的过程：

  validate_vendor_driver_dependency()
    → 检查 fx_robot.py
    → 检查 libMarvinSDK.so
    → 检查 robot.ini
    → 检查 UseEMG == 1
    → 检查双臂 JointPIDCtlType == 1

  load_vendor_sdk()
    → import SDK_PYTHON.fx_robot
    → 创建 Marvin_Robot()
    → fx_robot.py 使用 ctypes.CDLL 加载 libMarvinSDK.so

  对应位置：

  - src/xr_marvin_teleop/adapters/marvin.py:14
  - vendor/marvin/tj_fx_robot-master/SDK_PYTHON/fx_robot.py:322

  连接成功后，prepare_hardware() (src/xr_marvin_teleop/control/controller.py:325) 依次执行：

  读取 XR 初始状态
    → 要求 Grip/Trigger 已释放
    → adapter.connect()
    → 检查 SDK 版本
    → wait_for_fresh_feedback()
    → 确认无错误且机器人低速静止
    → configure_control_parameters()
         ├─ set_joint_kd_params()
         ├─ set_vel_acc()
         └─ set_tool()
    → enter_joint_impedance()
         ├─ set_state(A/B, state=3)
         └─ set_impedance_type(A/B, type=1)
    → enable_pd_feedforward()
    → 发送当前位置作为首个目标

  ### 2. 实时控制链路

  默认以 50 Hz 执行 execute_control_cycle() (src/xr_marvin_teleop/control/controller.py:793)：

  XR/PICO 手柄状态
    → xr_client.read_snapshot()
    → adapter.read_state()
    → 健康检查 / 反馈帧递增检查
    → OpenXR 位姿转换到 Marvin 坐标系
    → Grip 是否按下
    → FK 获取当前末端位姿
    → XrTargetMapper 计算目标末端位姿
    → IK 计算左右臂目标关节角
    → 关节速度限幅
    → controller._send_joint_command()
    → adapter.send_joint_command()
    → 厂商 SDK
    → libMarvinSDK.so
    → Marvin 控制器

  核心命令路径：

  controller._compute_q_command()
    → controller._compute_arm_q_command()
        → kinematics.fk_world()
        → pose_mapper.map_arm()
        → kinematics.ik_world()
    → controller._limit_joint_command_step()
    → controller._send_joint_command(q_rad)
    → adapter.send_joint_command(q_rad)

  适配器发送阶段会完成单位转换：

  14 关节弧度 q_rad
    → np.rad2deg()
    → set_joint_cmd_pose("A", 前7轴)
    → set_joint_cmd_pose("B", 后7轴)
    → send_cmd()

  对应位置：

  - IK 与目标生成：src/xr_marvin_teleop/control/controller.py:490
  - 命令发送入口：src/xr_marvin_teleop/control/controller.py:762
  - SDK 命令事务：src/xr_marvin_teleop/adapters/marvin.py:365
  - 双臂关节下发：src/xr_marvin_teleop/adapters/marvin.py:383

  ### 3. 状态反馈链路

  libMarvinSDK.so
    → fx_robot.Marvin_Robot.subscribe(DCSS)
    → adapter.read_state()
    → 解析左右臂反馈
    → 角度 deg → rad
    → MarvinRobotState
    → controller 健康检查和下一周期 IK

  反馈包括：

  - frame_serial：判断反馈是否持续更新
  - q_rad：当前关节位置
  - dq_rad_s：当前关节速度
  - arm_state：运行状态
  - impedance_type：阻抗模式
  - error_code：错误码
  - low_speed：低速/静止标志

  见 src/xr_marvin_teleop/adapters/marvin.py:283。

  ### 4. 异常与停止

  任何周期出现以下情况都会抛出异常并进入 finally 关闭：

  机器人错误码非零
  反馈连续 3 周期不更新
  双臂退出 state=3 / impedance type=1
  SDK setter 或 send_cmd 失败
  命令缓冲区忙超过 20 ms

  关闭链路：

  controller.shutdown_hardware()
    → adapter.set_idle()
        → set_state(A/B, state=0)
        → send_cmd_wait_response()
    → 等待反馈 arm_state == (0, 0)
    → adapter.release()
        → Marvin_Robot.release_robot()

  因此两个文件的职责边界很清楚：

  controller.py：决定“机器人应该去哪里”
  marvin.py：负责“如何安全地把命令交给厂商 SDK”
