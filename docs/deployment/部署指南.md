# 使用 uv 从零搭建 NUC 开发与运行环境

本文用于在全新的 NUC 上搭建本项目的 Python、ROS 2、PICO、Marvin 和 DAS 环境。

推荐基线：

- Ubuntu 22.04 LTS x86_64；
- ROS 2 Humble；
- 系统 Python 3.10；
- uv 管理项目根目录下的 `.venv`；
- 项目目录 `/home/zxcx/yubing/teleop`。

uv 只管理 Python 环境。ROS 2、XRoboToolkit PC Service、Marvin SDK、DAS 设备规则仍由系统包或厂家工具负责。

## 1. 部署范围与目录

项目的 `pyproject.toml` 已声明：

- 基础依赖：`numpy`、`mujoco`、`mcap`、`foxglove-schemas-protobuf`；
- `video` 可选依赖：`av`；
- `lerobot` 可选依赖：`pyarrow`；
- `das` 可选依赖：DAS 运行时 Python 包。

首次部署使用一个已提交的 commit；确认 `pyproject.toml`、`setup.py`、`.python-version`、`uv.lock`、`src/xr_marvin_teleop/cli/` 和 `legacy/ros2_ws/src/` 都存在。

核心链路需要 ROS、PICO PC Service、Marvin SDK 和硬件。DAS SDK、视频编码和 LeRobot 导出按需安装；DAS SDK 放在 `vendor/` 下但被 `.gitignore` 忽略，每台主机单独下载。

## 2. 安装系统基础依赖

先确认系统版本：

```bash
uname -m
lsb_release -ds
```

预期为 `x86_64` 和 Ubuntu 22.04。

安装基础工具：

```bash
sudo apt update

sudo apt install -y \
  git curl ca-certificates \
  build-essential cmake pkg-config \
  python3.10 python3.10-dev python3.10-venv \
  pybind11-dev libjson-c-dev \
  libgl1 libegl1 libglfw3 \
  ffmpeg \
  android-tools-adb v4l-utils \
  gstreamer1.0-tools \
  gstreamer1.0-plugins-base \
  gstreamer1.0-plugins-good
```

## 3. 安装 ROS 2 Humble

按照 [ROS 2 Humble 官方 Ubuntu 安装指南](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html) 配置 ROS 软件源，然后安装：

```bash
sudo apt update

sudo apt install -y \
  ros-humble-ros-base \
  ros-humble-rosbag2-storage-mcap \
  ros-humble-foxglove-msgs \
  python3-colcon-common-extensions \
  python3-rosdep
```

验证系统 ROS 环境：

```bash
source /opt/ros/humble/setup.bash

python3.10 -c 'import rclpy; print(rclpy.__file__)'
ros2 pkg prefix rosbag2_storage_mcap
ros2 interface show foxglove_msgs/msg/Grid
```

三条命令都必须成功。

## 4. 安装 uv

建议固定 uv 版本，避免不同 NUC 得到不同工具行为：

```bash
curl -LsSf \
  https://astral.sh/uv/0.12.15/install.sh \
  -o /tmp/uv-install.sh

sh /tmp/uv-install.sh
export PATH="$HOME/.local/bin:$PATH"

uv --version
```

参考：[uv 官方安装文档](https://docs.astral.sh/uv/getting-started/installation/)。

## 6. 创建兼容 ROS 的 uv 虚拟环境

完整 ROS 环境必须使用 Ubuntu 的 `/usr/bin/python3.10`。不要让 uv 下载独立 Python 作为 ROS 运行解释器，否则 apt 安装的 `rclpy` 默认不可见。

确认版本固定文件：

```bash
cd /home/zxcx/yubing/teleop
cat .python-version
```

预期输出：

```text
3.10
```

若文件不存在，可生成：

```bash
uv python pin 3.10
```

创建虚拟环境：

```bash
uv venv \
  --python /usr/bin/python3.10 \
  --system-site-packages
```

`--system-site-packages` 只让虚拟环境在运行时访问系统 ROS 包，uv 不会因此修改 apt 管理的包。参考：[uv venv 命令说明](https://docs.astral.sh/uv/reference/cli/#uv-venv)。

验证：

```bash
source /opt/ros/humble/setup.bash

.venv/bin/python - <<'PY'
import sys
import rclpy

print("Python:", sys.executable)
print("rclpy:", rclpy.__file__)
PY
```

解释器应位于项目的 `.venv/bin/python`，`rclpy` 应来自 `/opt/ros/humble/`。

`setup.py` 会在 `uv sync` 时编译 PICO 原生扩展，因此必须先安装 PC Service，使下面两个文件存在：

若文件不存在，先跳到第 10 节下载并安装 PC Service，再返回本节。

## 8. 同步 Python 依赖

NUC 基础运行环境建议安装视频依赖：

```bash
cd /home/zxcx/yubing/teleop
uv sync --frozen --extra video
```

需要 LeRobot 导出时再安装：

```bash
uv sync --frozen --extra video --extra lerobot
```

若正在修改依赖而不是部署锁定环境，先更新锁文件：

```bash
uv lock
uv sync --extra video
```

uv 会将当前项目以 editable 方式安装；optional dependencies 需要用 `--extra` 显式启用。参考：[uv 锁定与同步文档](https://docs.astral.sh/uv/concepts/projects/sync/)。

验证基础依赖：

```bash
print("core Python dependencies: OK")
PY
```

验证视频依赖：

## 9. 编译自定义 ROS 消息

```bash
cd /home/zxcx/yubing/teleop
source /opt/ros/humble/setup.bash

cd legacy/ros2_ws

rosdep install \
  --from-paths src \
  --ignore-src \
  --rosdistro humble \
```

ROS 官方建议在构建前运行 `rosdep`，再使用 `colcon build` 构建并 source workspace。参考：[ROS 2 colcon 教程](https://docs.ros.org/en/humble/Tutorials/Beginner-Client-Libraries/Colcon-Tutorial.html)。

验证：

```bash
uv run python - <<'PY'
import rclpy

```

## 10. 安装 XRoboToolkit PC Service

校验仓库中的安装包：

```bash
cd /home/zxcx/yubing/teleop

echo \
'61961067eb4b41f81ed7cae35f4690dbb0ddfefb329a12b24e0b90ebc46ada91  vendor/pico/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb' \
| sha256sum -c -

echo \
'6b2bb282405673d24abcb1980e3478b8f1052e90f7207b1f24cc56a59f8d8261  vendor/pico/XRoboToolkit-PICO-1.1.1.apk' \
| sha256sum -c -
```

只有两个结果都是 `OK` 才安装：

```bash
sudo apt install -y \
  ./vendor/pico/XRoboToolkit_PC_Service_1.0.0_ubuntu_22.04_amd64.deb
```

确认 SDK 文件：

```bash
test -f /opt/apps/roboticsservice/SDK/include/PXREARobotSDK.h
test -f /opt/apps/roboticsservice/SDK/x64/libPXREARobotSDK.so
```

启动服务：

```bash
bash /opt/apps/roboticsservice/runService.sh

pgrep -af RoboticsServiceProcess
ss -lnt | grep -E ':(63901|60061)\b'
```

进程只能有一个；`63901` 接收 PICO，`60061` 供本机 SDK 使用。

安装 PICO 应用：

```bash
adb devices -l
adb install -r vendor/pico/XRoboToolkit-PICO-1.1.1.apk
```

## 14. 日常启动顺序

每个新终端执行：


随后使用 uv 运行命令：

### 15.4 实机前检查

实机运行前至少确认：

- 物理急停可用且由现场人员持有；
- Marvin 有线网络路由正确；
- PICO 与 PC Service 只有一个活动实例；
- 双臂型号、A/B 映射和 Tool 配置正确；
- DAS 串口、相机软链接和标定文件来自当前 NUC；
- 不将 UI 停止按钮、`Ctrl+C` 或 PICO 按键当作急停。

## 16. 禁止操作

不要混用 Conda 与项目 `.venv`，也不要执行：

```bash
sudo uv ...
uv pip install --system ...
uv pip install --break-system-packages ...
```

这些操作会破坏 uv、系统 Python 与 ROS apt 包之间的边界。

完整顺序如下：

```text
系统依赖
→ ROS 2 Humble
→ uv
→ 基于 /usr/bin/python3.10 创建 .venv
→ 安装 XRoboToolkit PC Service
→ uv sync（编译 PICO 原生扩展）
→ 编译 teleop_msgs
→ 编译 Marvin SDK
→ 可选安装 DAS SDK
→ 分级验证
```
