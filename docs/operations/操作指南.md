# TeleOp 本机操作指南

本文档适用于 `/home/zxcx/yubing/teleop`，默认在 NUC Ubuntu 22.04 环境执行。

## 1. 环境检查

```bash
cd /home/zxcx/yubing/teleop
source /opt/ros/humble/setup.bash
uv sync

uv run python -c 'import sys; print(sys.executable)'
uv run teleop-collect --help
uv run teleop-hardware --help
uv run teleop-web --help
```

确认以下路径存在：

```text
config/collection.json
config/das_gripper.example.json
vendor/gen_finger_con_python_sdk_release/
vendor/marvin/
vendor/pico/
```

## 2. 配置

编辑配置文件：

```bash
${EDITOR:-vi} config/collection.json
${EDITOR:-vi} config/das_gripper.example.json
```

首次使用前确认：

- `robot.ip` 是 Marvin 实际 IP；
- `paths.das_sdk_root` 指向 `vendor/gen_finger_con_python_sdk_release`；
- 左右手指串口和相机设备名正确；
- `paths.output_root` 位于有足够空间的磁盘；
- 标定文件目录可写：`var/logs/`。

检查配置解析：

```bash
uv run teleop-collect \
  --config config/collection.json \
  --print-effective-config
```

## 3. 启动 Web 控制台

```bash
cd /home/zxcx/yubing/teleop
source /opt/ros/humble/setup.bash
uv run teleop-web
```

浏览器访问：

```text
http://127.0.0.1:4173
```
使用NUC时：
```bash
ssh -L 4173:127.0.0.1:4173 zxcx@192.168.1.12
```
启动自检：

```bash
uv run teleop-web --self-test
```

停止服务使用 `Ctrl+C`。Web 停止按钮不是物理急停，异常运动时必须使用现场急停。

## 4. 启动设备

推荐通过 Web 控制台启动设备。命令行启动必须显式提供安全确认：

```bash
uv run teleop-hardware \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping \
  --confirmed-robot-model Marvin
```

未确认安全参数时，程序应拒绝启动；不要绕过这些参数。

## 5. 采集 Episode

单独启动完整采集流程：

```bash
uv run teleop-collect \
  --config config/collection.json \
  --task "示例任务" \
  --operator "$USER" \
  --robot-model Marvin \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-joint-mapping
```

录制指定 Session：

```bash
uv run teleop-record \
  --config config/collection.json \
  --task "示例任务" \
  --operator "$USER" \
  --robot-model Marvin \
  --session session_$(date +%F) \
  --no-vision
```

开始前确认：

1. 工作区无人且无障碍物；
2. 机器人处于安全初始姿态；
3. PICO、Marvin、DAS 设备连接正常；
4. 磁盘空间充足；
5. 当前没有其他采集或复位进程。

## 6. 后处理与校验

对已完成 Episode 生成视频和校验结果：

```bash
uv run teleop-postprocess \
  /path/to/session/episode_000001 \
  --output-root var/dataset \
  --add-missing
```

验证 Episode：

```bash
uv run teleop-validate /path/to/session/episode_000001
```

查看人工审核信息：

```bash
uv run teleop-review /path/to/session/episode_000001
```

## 7. 标定与复位

DAS 标定：

```bash
uv run teleop-calibrate-das \
  --sdk-root vendor/gen_finger_con_python_sdk_release
```

机器人复位前必须确认急停和工作区：

```bash
uv run teleop-reset \
  --enable-hardware \
  --confirmed-estop \
  --confirmed-workspace-clear \
  --confirmed-robot-model Marvin
```

## 8. 数据迁移

迁移旧 Session：

```bash
uv run teleop-migrate SOURCE_DIR \
  --session SESSION_ID
```

迁移消息协议：

```bash
uv run teleop-migrate-messages OLD_EPISODE NEW_EPISODE
```

迁移前先备份原始数据，不要直接覆盖源目录。

## 9. 常见问题

### `KeyError: 'default'`

确认使用的是当前源码并重新同步环境：

```bash
uv sync
uv run teleop-collect --help
```

### 找不到 DAS SDK

```bash
test -f vendor/gen_finger_con_python_sdk_release/scripts/__init__.py
```

若失败，检查 `config/collection.json` 中的 `paths.das_sdk_root`。

### `PermissionError` 或无法写入日志

```bash
mkdir -p var/logs var/dataset
chmod u+rwx var/logs var/dataset
```

### 测试提示 MuJoCo 缺失

本机重构阶段可忽略 MuJoCo 仿真测试；采集、ROS 协议和硬件适配测试不应因此跳过。
